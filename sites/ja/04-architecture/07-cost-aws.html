AWS：構成と最適化

AWSではS3の非公開バケットをCloudFrontで配信します。大きな規模での費用の中心は、CloudFrontが読者から受けるリクエストの回数です。

構成

  • S3はOAC（オリジンアクセスコントロール）でCloudFrontからだけ読めるようにし、読者が開くページのURLは、CloudFront Functionsで閲覧アプリへ振り分けます。CLI 0.6に合わせた次のモジュールでは、この関数が動くのは既定のビヘイビアだけで、/_artifacts/や/_indexes/などへのリクエストは関数を通らず、CloudFrontのキャッシュかS3から返します。各ビヘイビアで圧縮を有効にします。
  • 配信する地域は既定でPriceClass_100です。WAF、独自ドメイン、証明書を使うと、その分の構成と費用が増えます。

大きな一覧の事前の圧縮

CloudFrontが自動で圧縮するのは1,000バイトから10,000,000バイトのファイルです。大きなサイトのindex.jsonはこれを超えるので、CLI 0.5.0以降はAWSに書くときに、index.jsonと検索の目次search/manifest.jsonを自分でgzipにして、Content-Encoding: gzipを付けて置きます。URL、Content-Type、キャッシュの設定は変わりません。

手元のnginxで5万件のサイトを配り、通信を絞った条件（CPU 4倍遅く、往復150 ms、下り1.6 Mbps）で測ると、index.jsonは転送が約2.48 MB（展開後約45.9 MB）になり、3回とも約12.8秒で読み込みが終わりました（20秒の制限の内）。2026年10月18日の計測で、AWSでの実際の配信の計測ではありません。記録は製品のISSUE-112（英語）にあります。圧縮しても、ブラウザが展開して読み込む量は変わりません。

一度0.5.0以降で書いたサイトには、それより古いCLIで書き込まないでください。圧縮を止める設定や、自動で元の形式に戻す仕組みはありません。移る手順は「閲覧アプリ・CLI・Actionsを更新する」にあります。

費用のモデル

S3（us-east-1）とCloudFront（PriceClass_100）の2026年10月18日の公開価格を当てはめた30日の見積もりです。想定（ページ数の代用、公開と検索の回数を含む）はCloudflareのページと同じです。

M$2.11$0.01 / $0.99 / $1.11 / $0.00 / $0.00 / $0.00

内訳は項目ごとに1セント単位に丸めているので、足し合わせると月額と1セント違うことがあります。

  • CLI 0.6に合わせたモジュールが前提です。この版はまだ公開されておらず、AWSでは実際の環境でまだ確かめていません。いま公開されているモジュール0.1.1での見積もりは含みません。
  • キャッシュの無効化はしないので、その費用はありません。
  • CloudFront Functionsの呼び出しは、月にS 41,500回、M 830,000回、L 4,150,000回と見積もっています。料金は100万回あたり$0.10で、月200万回の無料枠を引いた残りにかかります。
  • CloudFrontの無料枠（月1 TB、1,000万リクエスト）をこの用途に使える前提です。Lの転送は約877 GBで、1 TBの枠に近いので、読者が1回の訪問で開くページが少ないと超えます（1回の訪問で1ページだけなら、Lは$241.07）。
  • 読者は1回の訪問で3ページ開き、再読み込みはしないと仮定しています。Lで1回の訪問ごとに1回再読み込みすると、一覧が変わっていなければ$48.28、変わっていれば$66.80です。
  • PriceClass_100の中で最も高い地域の単価では、Lが$43.96になります。
  • S3まで届く割合を変えた場合のLは、米国・カナダの単価で、サイトの登録情報と一覧（sites.json、meta.json、index.json）がすべてキャッシュに当たれば$36.60、ブラウザのキャッシュで済んだもの以外のすべてのリクエストがS3まで届けば$48.59です（最も高い地域の単価では$42.76と$54.75）。どちらも仮定を変えた一例で、予想の幅ではありません。
  • プレビュー、404、登録の反映、閲覧アプリの配置、WAFの費用は含みません。

前提と内訳は製品の費用のモデル（英語）にあります。最新の価格はCloudFrontとS3の料金で確かめてください。
