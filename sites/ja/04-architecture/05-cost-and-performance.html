コストとパフォーマンス

費用と速さは、公開と閲覧の処理のどこで、何がどれだけ動くかで決まります。このページでは共通の要因と、これまでの計測の結果を、計測の条件とあわせて示します。数字は計測した条件での値で、性能や請求額の保証ではありません。

要点費用と時間を決めるのは、Artifactの数とサイトの一覧の大きさ、公開の回数、閲覧の回数です。数字はすべて計測した条件でのもので、保証値ではありません。

費用と時間が決まる要因

場面何が動くか
保存公開したArtifact、一覧、検索のデータ、プレビューのリビジョン（保持期間の間）、閲覧アプリのファイル
公開ロックと状態の記録の読み書き、変わったファイルと一覧の書き込み。Artifactが1つ変わっただけでも、サイトのindex.json全体を読み書きします。変更がなければ小さな記録の読み書きだけです
閲覧閲覧アプリ、サイトの一覧、Artifactの取得。Artifactは、読者のブラウザが読み込むたびに配信先がストレージに確かめます。一覧は配信先のキャッシュに最大5秒残るので、アクセスが少ないサイトほどストレージまで届く割合が高くなります。キャッシュに当たっても、読者への転送の費用がなくなるとは限りません
検索検索のデータのうち、必要な区画だけの取得

キャッシュの指示

CLIは、書くファイルの種類ごとに次のキャッシュの指示を付けます。CDNのキャッシュの削除はしません。

対象Cache-Control
閲覧アプリの入口のファイルno-cache, max-age=0, must-revalidate, stale-if-error=0
ハッシュ付きの閲覧アプリのファイルpublic, max-age=31536000, immutable
登録情報、サイトの概要（meta.json）、一覧（index.json）public, max-age=0, s-maxage=5, must-revalidate, stale-if-error=0
公開したArtifactとそれが使うファイル、検索の目次、プレビューpublic, max-age=0, s-maxage=0, must-revalidate, stale-if-error=0
検索のデータの区画public, max-age=31536000, immutable
内部の記録no-store（読者には返さない）

公開したあと、読者のブラウザが新しく読み込めば、一覧は最大5秒、Artifactはすぐに新しい内容になります。その代わり、ストレージまで届くリクエストは、長くキャッシュする場合より増えます。Cloudflareのモジュール0.2.0は、404の応答も配信先にキャッシュしません。

ブラウザでの計測

合成したArtifact（1千から5万件）のサイトを、手元のnginxで配信して計測しました。Apple M4（32 GB）、Chromium 153、3回の中央値です。nginxは圧縮していません。閲覧アプリは計測時点の版で、いまの版での再計測ではありません。

  • 通信を絞った条件（CPU 4倍遅く、往復150 ms、下り1.6 Mbps）では、1千件で13.8秒かかり、5千件以上はindex.jsonの読み込みが20秒の制限を超えて失敗しました。

  • 5万件のうち18,956件（約38%）は、抜粋のデータの上限のため抜粋なしになりました。

詳しい条件と、ここに載せていない数値は、製品の計測の報告（英語）にあります。

CLIのメモリ

CLIは公開元をメモリに読み込んで処理します。Mac（arm64、32 GiB）の手元のファイルシステムに公開し、ピーク時のメモリ（RSS）を3回の中央値で測りました。クラウドへのアップロードやGitHubのランナーでは測っていません。2026年10月17日のビルドでの計測で、いまのCLIでの再計測ではありません。条件の詳細は製品のメモリの計測（英語）にあります。

公開元初回 / 変更なし / 差分あり
小さなファイル10,000個（195.3 MiB）749.9 / 236.8 / 783.9 MiB
256 MiBのファイル1つ542.2 / 278.0 / 541.8 MiB
512 MiBのファイル1つ1054.3 / 534.3 / 1055.5 MiB
大きなファイルで合計1000.2 MiB2032.1 / 1023.6 / 2032.7 MiB

大きな公開元では、書き込みを伴う公開で公開元の約2倍、変更なしで約1倍のメモリを使います。文書で示している対応の範囲は、1ファイル512 MiB、1回の公開の合計1 GiBまでです。CLIはこれを超える入力を拒否しないので、ランナーのメモリに注意してください。

費用のモデル

CLI 0.6のキャッシュの指示で月額を見積もりました。読者の通信量は、手元で閲覧アプリを動かして計測した値を使い、URLの種類ごとに、ストレージまで届く割合を仮定して当てはめています。公開の操作の回数と保存する量は、CLI 0.6で計測し直しました。価格は2026年10月18日の公開価格です。実際の請求や総予算ではありません。配信先ごとの内訳は各ページにあります。

想定は3つです。Sは5サイト（各200ページ）を1日1,000回、Mは30サイト（各2,000ページ）を1日20,000回閲覧します。LはMに5万ページのサイトを1つ加え、1日100,000回閲覧します。

想定Cloudflare（R2）の月額AWS（S3とCloudFront）の月額
S$0.09$0.10
M$1.90$2.11
L$6.12$37.80

Cloudflareは無料枠を引く前の額、AWSは無料枠をこの用途に使える前提で、米国・カナダの単価での額です。キャッシュの削除や無効化の費用はもうありません。

  • 読者は1回の訪問で3ページ開き、再読み込みはしないと仮定しています。
  • ストレージまで届く割合は、一覧とArtifactを100%、ハッシュ付きの閲覧アプリのファイルを10%、検索のデータの区画を50%と仮定しています。一覧の100%は、アクセスが少なくキャッシュに残らない場合を見込んだ多めの仮定です。どれも実際のアクセスで測った値ではありません。
  • AWSの額は、CLI 0.6に合わせたモジュールを前提にしています。この版はまだ公開されていません。AWSでは実際の環境でまだ確かめていません。
  • プレビュー、404、登録の反映、閲覧アプリの配置の費用は含めていません。
