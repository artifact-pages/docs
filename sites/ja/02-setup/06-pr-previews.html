PRプレビューを使えるようにする

最後に、プルリクエストで変えたArtifactを、マージの前に閲覧アプリで読めるようにします。チームのリポジトリに、共通のプレビューのワークフローを呼び出すワークフローを1つ足します。

  1. 1インフラを構築する
  2. 2管理リポジトリを準備する
  3. 3閲覧アプリをデプロイする
  4. 4サイトを登録する
  5. 5最初のサイトを公開する
  6. 6PRプレビューを使えるようにする

ワークフローを置く

.github/workflows/preview.yml / acme/sre
name: Preview docs
on:
  pull_request:
    paths: ['docs/**']
permissions:
  contents: read
concurrency:
  group: preview-${{ github.event.pull_request.number }}
  cancel-in-progress: true
jobs:
  preview:
    if: github.event.pull_request.head.repo.full_name == github.repository
    permissions:
      contents: read
      pull-requests: write
      # AWSでは id-token: write も足す
    uses: acme/platform-admin/.github/workflows/preview-site.yml@main
    with:
      site: sre
    secrets: inherit
  • ifで、同じリポジトリのブランチからのプルリクエストに限ります。フォークからのプルリクエストに認証情報を渡さないためです。共通のワークフローも同じ確認をしますが、呼び出す側でも止めておきます。
  • pull-requests: writeは、このプレビューのジョブだけに付けます。共通のワークフローは、プルリクエストにプレビューのコメントを付けます。本公開のジョブには要りません。
  • 製品のartifact-pages/preview-actionを直接使う場合、コメントの入力commentの既定はfalseで、コメントは付きません。共通のワークフローは内部でcomment: trueを指定しています。
  • AWSでは、このジョブのsub（Environmentを使わなければrepo:acme/sre:pull_requestの形）をsatellite_github_subjectsに入れておきます。

プレビューを作るたびに配信先に書き込むので、すべてのプルリクエストではなく、ラベルを付けたものだけにする運用もあります。その場合はonとifにラベルの条件を足します。

レビューする人に見えるもの

  1. プルリクエストに、サイトごとに1つのコメントが付きます。変わったArtifactの一覧とプレビューへのリンクがあり、プレビューを作り直すたびに書き換わります。
  2. リンクを開くと、閲覧アプリの中でプレビューが開きます。左には、変更したArtifactと、変更したファイルの影響を受けたArtifactだけが並びます。
  3. サイトのトップのPreviewsからも、そのサイトのプレビューの一覧を開けます。

プレビューに含まれるのは、プルリクエストで追加・変更したArtifactと、変更したCSSや画像を参照しているArtifactです。プレビューの内容は、プルリクエストの先頭のコミットそのものです。削除したArtifactだけの変更など、プレビューするArtifactがない場合は、結果がno-previewになり、正常に終わります。

URL開くもの
/sre/_previews?group=pr%3A42プルリクエスト#42の最新のプレビューの一覧。新しいプレビューができると、その内容に変わります。
/sre/_previews/<コミットのSHA>/<Artifactのパス>そのコミットのプレビューのArtifact。あとから変わりません。

プルリクエストを閉じたあと

プルリクエストをマージしたり閉じたりしても、プレビューは自動では消えません。配信先の保持期間（Terraformのpreview_retention_days）が過ぎると、配信先が削除します。削除は配信先が非同期に行うので、ちょうどその日数で消えるとは限りません。

期間を待たずに消したい場合は、CLIで削除します。

ターミナル
$ artifact-pages preview remove --site sre --group pr:42 --config github://acme/platform-admin/artifact-pages.yaml --dry-run
$ artifact-pages preview remove --site sre --group pr:42 --config github://acme/platform-admin/artifact-pages.yaml

本公開のArtifactからファイルを消しても、そのファイルのプレビューは消えません。サイトを取り下げると、そのサイトのプレビューもまとめて削除されます。

導入の完了

これで、最初のチームが自分のリポジトリからArtifactを公開し、プルリクエストをプレビューで確かめられるようになりました。次のチームを受け入れるときは「新しいチーム・サイトを受け入れる」に進みます。
