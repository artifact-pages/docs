インフラを構築する

資料を置くストレージと、それを読者に届ける配信の仕組みを、CloudflareかAWSに用意します。どちらも製品が公開しているTerraformモジュールを呼び出して作ります。このステップで閲覧アプリやサイトはまだ置きません。それは次のステップからです。

このステップで用意するもの

モジュールを適用すると、配信先に次のものがそろいます。閲覧アプリ、サイトの登録情報、各サイトの資料はまだ入っていません。これらは、このあとのステップで置きます（AWSでは、404の応答に使うページだけをモジュールが置きます）。

  • 非公開のストレージ。CloudflareではR2のバケット、AWSではS3のバケットです。閲覧アプリと公開された資料は、すべてここに入ります。バケット自体は直接公開しません。
  • 読者が開くホスト名。Cloudflareでは、お使いのゾーンにあるホスト名（例：docs.example.com）です。AWSでは、最初はCloudFrontが割り当てるホスト名をそのまま使え、独自ドメインはあとから付けられます。
  • URLの振り分けとキャッシュの規則。ページや見出しのURLを閲覧アプリへ届け、内部用の記録はストレージの中身を返さないようにします。資料の種類ごとにキャッシュの長さとHTMLの応答ポリシーも決まります。
  • PRプレビューの保持期間。プレビューは、指定した日数が過ぎると自動で削除されます。日数はTerraformの入力preview_retention_daysで決め、CLIの設定ファイルには書きません。
  • 公開ジョブの認証情報。管理リポジトリのジョブ（閲覧アプリの配置とサイトの登録）と、各チームのジョブ（自分のサイトの公開とプレビュー）が配信先に書き込むための認証情報です。用意のしかたは配信先によって異なります（下の表を参照）。
閲覧の制限

サイトを登録しても、読める人は限定されません。Artifact Pagesには、ユーザーアカウントやログイン、サイトごとの閲覧権限がありません。ホスト名に届く人は、登録されたどのサイトも読めます。社内だけに見せたい場合は、ホスト名の単位で制限します。方法は各配信先のページで説明します。

CloudflareとAWSのどちらを選ぶか

できることはほぼ同じで、違いは主に、ホスト名の用意のしかたと、ジョブの認証のしかたです。社内ですでに使っているほうを選ぶのが近道です。

CloudflareAWS
ストレージと配信R2と、ゾーンのルールS3と、CloudFront
ホスト名Cloudflareで管理しているゾーンの中のホスト名が必要です。CloudFrontのホスト名（*.cloudfront.net）で始められます。独自ドメインは任意です。
ジョブの認証R2のアクセスキーやAPIトークンを自分で発行し、GitHubのシークレットに入れます。モジュールは発行しません。モジュールがIAMロールを作り、各ジョブはGitHubのOIDCでそのロールを引き受けます。GitHubに長期のキーは置きません。
閲覧の制限IPアドレスでの制限とHTTPSのみの許可を、モジュールで設定できます。本人の認証にはCloudflare Accessを別に設定します。IPアドレスでの制限を、モジュールでAWS WAFとして設定できます。本人の認証は別の仕組みが必要です。

費用は、保存する量、配信する量、キャッシュの削除、WAFを使うかどうかで変わります。ここでは一律にどちらが安いとは言えません。費用がどこで生まれるかは「コストとパフォーマンス」で説明します。

共通の流れ

どちらの配信先でも、手順の形は同じです。自分のTerraformの設定（以下、呼び出し側）からモジュールを呼び出します。

  1. モジュールを指定する。Terraform Registryのアドレスをsourceに、使うバージョンをversionに書きます。バージョンは範囲でなく、0.1.1のように正確に固定します。
  2. プロバイダーと入力を書く。プロバイダー（cloudflareかaws）の設定は呼び出し側で行います。必須の入力は、どちらのモジュールも4つです。
  3. 計画を確かめて適用する。terraform init、terraform planで作られるものを確かめてから、terraform applyを実行します。
  4. 出力を取り出す。モジュールは、CLIの設定ファイルにそのまま貼れる配信先の設定を出力します。呼び出し側でこれをoutputとして公開しておくと、terraform outputで読めます。
ターミナル / 呼び出し側のディレクトリ
$ terraform init
$ terraform plan
$ terraform apply

Terraform Registryを使えない環境では、モジュールのGitリポジトリを直接指定できます。その場合はversionを書かず、タグを?ref=で固定します。

HCL / Registryの代わりにGitを使う
source = "git::https://github.com/artifact-pages/terraform-cloudflare-artifact-pages.git?ref=v0.1.1"
# AWSは terraform-aws-artifact-pages.git
