Cloudflareに構築する

R2のバケットと、お使いのゾーンのルールで、Artifact Pagesの配信環境を作ります。モジュールの呼び出しはTerraformで行い、公開ジョブの認証情報はCloudflareのダッシュボードで発行します。

  1. 1インフラを構築する
  2. 2管理リポジトリを準備する
  3. 3閲覧アプリをデプロイする
  4. 4サイトを登録する
  5. 5最初のサイトを公開する
  6. 6PRプレビューを使えるようにする

できあがるもの

  • 非公開のR2バケット。名前は既定でartifact-pagesです。閲覧アプリと公開されたArtifactはすべてここに入ります。
  • 指定したホスト名。R2のカスタムドメインとしてバケットにつなぎます。バケットのr2.devのURLは無効にしたままにします。
  • ゾーンのルール。URLの振り分け、キャッシュ、応答ヘッダー、HTMLを書き換えるCloudflareの機能を止める設定の4種類です。ページのURLは閲覧アプリへ届き、内部用の/_control/以下のURLでもストレージの中身は返りません。
  • PRプレビューの保持期間。バケットのライフサイクルの規則として、_previews/以下を指定日数で削除します。

WorkerやPagesは使いません。公開ジョブ用の認証情報もモジュールは作らないので、認証情報で自分で発行します。

先に必要なもの

  • R2の利用を開始しておく。ダッシュボードのR2の画面から、アカウントでR2を使い始める手続きを済ませます。支払い方法の登録を求められることがあります。
  • Cloudflareで管理しているゾーン。読者が開くホスト名は、このゾーンの中に置きます（例：docs.example.com）。
  • アカウントIDとゾーンID。どちらも32桁の16進数です。ダッシュボードで確認できます。
R2が未開始

バケットの作成が403、コード10042で失敗したら、R2の利用開始を確かめてください。このコードは、アカウントでR2を使える状態になっていないことを示します。ほかの理由の403もあるので、コードまで確かめます。

利用を開始した直後は、R2のS3互換のエンドポイントへのTLS接続が数分ほど失敗することがあります。少し待ってからやり直してください。

認証情報

認証情報は2種類あり、混ぜずに分けて扱います。どちらの値も、Terraformの変数、設定ファイル、リポジトリには書きません。

Terraformが使うAPIトークン

モジュールを適用する人（またはジョブ）が使います。呼び出し側のCloudflareプロバイダーに、環境変数CLOUDFLARE_API_TOKENなどで渡します。次の権限が必要です。

  • R2のストレージ、カスタムドメイン、ライフサイクルの管理
  • ゾーンのTransform Rules Edit、Cache Rules Edit、Config Rules Edit
  • ホスト名を制限する場合だけ、ゾーンのZone WAF Edit

公開ジョブが使う認証情報

管理リポジトリのジョブと各チームのジョブが、CLIを通じて使います。GitHubのシークレットに入れ、ジョブで環境変数として渡します。方式は次の2つから選べます。

方式環境変数用意するもの
R2のキーとAPIトークンCF_R2_ACCESS_KEY_ID
CF_R2_SECRET_ACCESS_KEY
CF_API_TOKEN		R2のAPIトークンで発行したアクセスキーIDとシークレット。キャッシュを削除する実行のために、ゾーンのCache Purgeを持つAPIトークン。
APIトークン1つCF_API_TOKENだけアカウントのAPIトークン1つ。CLIがこのトークンからR2のキーを導きます。権限は下のとおりです。

R2のキーが2つとも設定されていればそちらが使われ、片方だけでは失敗します。APIトークン1つの方式では、試し実行（--dry-run）や変更のない実行でもトークンが必要です。R2のキーの方式では、APIトークンはキャッシュを削除する実行でだけ使います。コマンドごとの要否は製品のCloudflareの導入ガイドに表があります。

APIトークン1つの方式では、アカウントのAPIトークンを作り、次の2つの権限を付けます。

権限対象
Workers R2 Storage Bucket Item WriteArtifact Pagesのバケットだけ。リソースはcom.cloudflare.edge.r2.bucket.<アカウントID>_default_<バケット名>です（このモジュールはデータの保存地域の指定（jurisdiction）をしないのでdefault）。
Cache Purgeホスト名を置いたゾーンだけ。
サイトの分離

バケット全体に書ける認証情報は、サイトごとに分離されません。同じ環境変数名を使っても、管理リポジトリと各チームで同じ値を共有する必要はありません。ただし、どちらもバケット全体に書ける認証情報なら、あるチームのジョブがほかのサイトの領域にも書けてしまいます。チームのジョブを自分のサイトの領域だけに限るには、R2の一時的な認証情報を、サイトごとのプレフィックスに絞って発行する構成が必要です。CLIはこの発行や更新をしません。手順は製品ガイドのOptional delegated publisherにあります。

モジュールを呼び出す

呼び出し側のTerraformの設定に、モジュールとプロバイダー、あとで使う出力を書きます。値は例なので、お使いのアカウント、ゾーン、ホスト名に置き換えてください。

HCL / main.tf
provider "cloudflare" {}    # トークンは CLOUDFLARE_API_TOKEN で渡す

module "artifact_pages" {
  source  = "artifact-pages/artifact-pages/cloudflare"
  version = "0.1.1"

  account_id             = var.cloudflare_account_id
  zone_id                = var.cloudflare_zone_id
  public_hostname        = "docs.example.com"
  preview_retention_days = 14
}

output "artifact_pages_deployment_config_yaml" {
  value = module.artifact_pages.artifact_pages_deployment_config_yaml
}

このほか、cloudflare_account_idとcloudflare_zone_idの変数宣言と、プロバイダーのバージョン指定（cloudflare/cloudflareの>= 5.24.0, < 6.0.0）を書きます。

入力内容
account_id必須R2とゾーンを持つアカウントのID。
zone_id必須ホスト名を置く、既存のゾーンのID。
public_hostname必須読者が開くホスト名。https://やパスは付けません。
preview_retention_days必須PRプレビューを残す日数。1から36500までの整数で、既定値はありません。14は例です。
bucket_name任意作るバケットの名前。既定はartifact-pagesで、アカウントに同じ名前があると作れません。
waf_custom_rules任意ホスト名の制限。既定はnullで、何も制限しません。下の節を参照してください。

すべての入力は、モジュールのREADMEにあります。公開ジョブの環境変数名を変えたい場合や、チームごとに読み取り用の認証情報を分ける場合の入力もそこにあります。

既存の設定があるゾーンでは

モジュールは、ゾーンの4種類のルール（変換、キャッシュ、応答ヘッダー、設定）を、それぞれ丸ごと管理します。ゾーンにすでにこれらのルールがあると、最初の適用が失敗するか、既存のルールが置き換えられます。適用する前に、次を確かめてください。

  • 既存のルールを取り込む。すでにあるルールセットはterraform importで取り込み、現在の名前を対応する*_ruleset_nameに、既存のルールをすべて対応するexisting_*_rulesに渡します。名前はあとから変えられません。
  • 既存のライフサイクルの規則を引き継ぐ。モジュールはバケットのライフサイクルの規則も丸ごと管理します。残したい規則はadditional_lifecycle_rulesに渡します。
  • つないであるホスト名。ホスト名がすでにバケットにつながっている場合は、connect_custom_domain = falseにして、つながりとTLSの設定を別に確かめます。
  • 既存のバケット。モジュールは毎回バケットを作ります。既存のバケットを使うなら、適用の前に取り込むか、配信とライフサイクルのサブモジュールだけを使います。

取り込むときのアドレスとIDは、モジュールのREADME（Resource ownership and apply review）にあります。新しいゾーンや、これらのルールがまだないゾーンでは、この節の作業は要りません。

ホスト名へのアクセスを制限する

社内からだけ読めるようにしたい場合は、waf_custom_rulesの2つのプリセットで、ホスト名に届く通信を絞れます。

HCL / module "artifact_pages" に追加
waf_custom_rules = {
  presets = {
    https_only   = true
    ip_allowlist = ["192.0.2.10/32"]   # 説明用のアドレス。実際の社内の公開CIDRに置き換える
  }
}
  • https_onlyは、暗号化されていない接続と443番以外のポートを拒否します。HTTPSへのリダイレクトはしません。
  • ip_allowlistは、一覧にないIPv4、IPv6のアドレスからの通信を拒否します。空、重複、正しくない値は指定できません。
  • 両方を指定すると、どちらかに反する通信を拒否する1つのルールになります。
適用の前に

自分の公開IPアドレスを先に確かめてください。一覧に自分の接続元が入っていないと、適用した時点で自分も読めなくなります。IPv4とIPv6の両方の経路がある環境では、両方を確かめます。

Terraformが使うAPIトークンにZone WAF Editを足しておきます。WAFのルール数や使えるアクションは契約プランで異なるので、プランも確かめてください。

このプリセットは、通信の出どころ（IPアドレス）と経路（HTTPS）で絞るフィルターです。誰が読んでいるかは確かめません。人単位で認証したい場合は、ホスト名にCloudflare Accessを設定します。モジュールは認証を設定しないので、Accessは別に設定し、実際に効いていることを確かめてください。

計画を確かめて適用する

ターミナル / 呼び出し側のディレクトリ
$ terraform init
$ terraform plan
$ terraform apply

計画では、作られるもののほか、既存のルールセットやライフサイクルの規則が置き換えられたり消えたりしないかを確かめます。適用したら、次の2つを確かめてください。

  • バケットのr2.devのURLが無効になっていること。有効なままだと、ゾーンのルールを通らずにバケットの中身が読めてしまいます。
  • ホスト名がバケットにつながり、TLSが有効になっていること。

プレビューの削除はCloudflareが非同期に行うので、指定した日数ちょうどで消えるとは限りません。プレビューを今すぐ見えなくする手段としては使えません。

出力を次のステップに渡す

モジュールは、CLIの設定ファイルに入れる配信先の設定を出力します。秘密の値は含みません。

ターミナル / 出力の例

  "accountId": "0123456789abcdef0123456789abcdef"

  "publicBaseURL": "https://docs.example.com"
  "zoneId": "fedcba9876543210fedcba9876543210"

この内容を、次のステップで管理リポジトリのartifact-pages.yamlに入れ、CLIと閲覧アプリのバージョン、登録するサイトを書き足します。公開ジョブの環境変数名を既定から変えた場合は、その名前もここに出力されます。
