サイトを登録する

最初のチームのサイトsreを登録します。登録すると、acme/sreの指定したディレクトリから、このサイトに公開できるようになります。

  1. 1インフラを構築する
  2. 2管理リポジトリを準備する
  3. 3閲覧アプリをデプロイする
  4. 4サイトを登録する
  5. 5最初のサイトを公開する
  6. 6PRプレビューを使えるようにする

sitesに書く

artifact-pages.yaml / 管理リポジトリ（説明用の例）
sites:
  sre:
    name: SREチーム
    description: 運用手順と障害の振り返り
    repository: acme/sre
    sourcePath: docs
項目内容
サイトID（sre）必須URLの最初の部分になります。英小文字と数字をハイフンでつないだ形で、assetsは使えません。リポジトリ名から自動では決まりません。
name必須サイトの一覧に出る名前。
description任意サイトの一覧に出る説明。
repository必須公開元のGitHubのリポジトリ。owner/repositoryの形。
sourcePath必須公開するディレクトリ。リポジトリの中の相対パスで、全体なら.。

同じリポジトリの別のディレクトリを、別のサイトとして登録できます。同じリポジトリとディレクトリの組を2つのサイトに登録することはできません。

完全な一覧

sitesは、登録するサイトのすべてです。ここにないサイトは、反映したときに取り下げられ、公開済みのArtifactとプレビューも削除されます。すでにサイトがある環境でこの例を貼るときは、既存のサイトを消さないでください。sitesそのものを書かないと反映は失敗し、sites: {}はすべてのサイトの取り下げを意味します。

試し実行してから反映する

生成したregistry.ymlが反映を受け持ちます。

  1. 設定の変更をプルリクエストにします。registry.ymlが試し実行し、何が変わるかをジョブの概要に出します。結果はplannedです。
  2. 内容がよければマージします。mainへのプッシュで、配信先の登録が更新されます。結果はsynced、変わるものがなければno-opです。

手元からは次のコマンドで同じことができます。

ターミナル / 管理リポジトリ
$ artifact-pages registry sync --config artifact-pages.yaml --dry-run
$ artifact-pages registry sync --config artifact-pages.yaml

反映すると、閲覧アプリのサイトの一覧にSREチームが出ます。Artifactはまだないので、開いても空です。

登録が認めること

  • 公開のとき、CLIは配信先の登録を読み、公開しようとしているリポジトリとディレクトリが登録どおりかを確かめます。チームが自分で読んだ設定に自分を書き足しても、登録にはなりません。
  • この確認は、配信先の権限の代わりにはなりません。バケットに広く書ける認証情報を持つ人は、CLIを通さずに書き込めます。AWSでは、サイトのIAMロールがTerraformで作られていることも必要です（IAMロールとOIDC）。
  • 登録は、読者を限定しません。
