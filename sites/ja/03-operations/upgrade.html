閲覧アプリ・CLI・Actionsを更新する

閲覧アプリ、CLI、GitHub Actionsは、それぞれ別のバージョンでリリースされます。管理リポジトリのartifact-pages.yamlで閲覧アプリとCLIの版を固定し、それを書き換えて更新します。

版を固定する

artifact-pages.yaml / 管理リポジトリ
cli:
  version: 0.5.2   # 公開や登録を行うCLI
web:
  version: 0.4.1   # app deploy が置く閲覧アプリ
  • 値は0.5.2のような正確な版です。先頭のv、範囲、latestは書けません。
  • 入れてあるCLIは、cli.versionが自分と違う版を指していれば、その版をダウンロードし、チェックサムを確かめてから実行を任せます。
  • 製品のActionsの版（いまはv0.3.0）は、CLIの版とは別の番号です。各Actionsは、使えるCLIの範囲（v0.3.0では>=0.5.0 <0.6.0）を持っています。

いまの版はすべて0.xのプレリリースで、版をまたぐ互換性は約束されていません。ただし、CLIは書き込む前に、配置された閲覧アプリがその形式を読めるかを毎回確かめます。

通常の更新

  1. cli.versionとweb.versionのうち、上げるほうを書き換えます。
  2. config checkで、そのCLIが書く形式と、配信先にいま入っている形式を、その閲覧アプリが読めるかを確かめます。書き込みはしません。
  3. 登録を反映し、閲覧アプリを変えた場合は配置します。それぞれ試し実行で確かめてから実行します。
ターミナル / 管理リポジトリ
$ artifact-pages config check --config artifact-pages.yaml
Config and stored formats are compatible with web.version.
$ artifact-pages registry sync --config artifact-pages.yaml
$ artifact-pages app deploy --config artifact-pages.yaml

CLIの新しい版が、共通のワークフローで使っている製品Actionsの範囲を外れる場合は、先に新しいCLIで共通のワークフローを作り直します（「共通の公開・プレビューの仕組みを更新する」）。範囲の外の版を指定すると、ジョブはダウンロードの前に終了コード2で止まります。

形式が変わる更新

新しい版で保存の形式が変わり、古い閲覧アプリでは読めなくなる場合は、config checkが失敗します。そのときは、次の順で計画的に移ります。

  1. registry sync --accept-breakingで登録を新しい形式にします。
  2. app deploy --accept-breakingで新しい閲覧アプリを置きます。
  3. 新しいCLIで、すべてのサイトを公開し直します。

--accept-breakingがあるのはregistry syncとapp deployだけです。公開し直すまでの間、まだ古い形式のサイトを開くと、閲覧アプリはThis site needs to be republishedと表示します。

1回だけ別のCLIを使う

設定を変えずに、1回の実行だけ別のCLIを使えます。優先順は、コマンドの--cli-version、環境変数ARTIFACT_PAGES_CLI_VERSION、製品Actionの入力cli-version、設定のcli.versionの順です。

ターミナル
$ artifact-pages --cli-version 0.5.2 site sync --site sre --config artifact-pages.yaml --dry-run

互換性の確認とActionsの範囲の確認は、この場合も行われます。管理リポジトリの共通のワークフローには、この指定を渡す入力がありません。チームのジョブで試すには、直接CLIを動かします。

固定のない古い環境を追いつかせる

  • 設定にcliもwebもない環境では、入れてあるCLIがそのまま動きます。古いCLIはこれらのキーを知らずに拒否するので、まず使うCLIとActionsを、これらのキーに対応する版に上げます。そのあとでweb.version（必要ならcli.version）を書き足します。閲覧アプリとCLIのリリースが分かれたあとのCLIでは、cli.versionだけを書いてweb.versionがないと、app deployは--archiveを指定しない限り閲覧アプリを選べず、終了コード2で止まります。
  • 版の記録がない古いサイトは、互換かどうか判断できないものとして扱われます。登録を反映し、全サイトを公開し直して記録を作ってから閲覧アプリを置くか、上の「形式が変わる更新」の順で移ります。
  • AWSでは、CLI 0.5.0以降が、サイトの一覧と検索のデータを圧縮して保存します。一度0.5.0以降で公開したサイトには、そのあと0.5.0より古いCLIで書き込まないでください。移る前に、そのサイトに書き込むすべての実行（手元、定期実行、Actions）を0.5.0以降にそろえます。

前の版に戻す

閲覧アプリは、保存の形式が変わっていなければ、web.versionを前の版にしてconfig checkとapp deployを行えば戻せます。CLIは、上のAWSの制約のように、新しい版で書いたデータを古い版が扱えない場合があります。設定を元に戻せば必ず安全に戻せる、というわけではないので、戻す前にconfig checkで確かめてください。
