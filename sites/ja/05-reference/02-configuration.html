リファレンス

設定ファイル

設定ファイルartifact-pages.yamlは、配信先、CLIと閲覧アプリの版、登録するサイトを書くYAMLです。認証情報の値は書かず、値を読む環境変数の名前だけを書きます。

どの設定が使われるか

  1. --config（何度でも指定でき、指定した順に重ねる）
  2. 環境変数ARTIFACT_PAGES_CONFIG
  3. いまのディレクトリのartifact-pages.yaml
  4. artifact-pages config set-defaultで保存した指定

最初に見つかったものだけを使い、ほかと暗黙に合成しません。ただしregistry setupとregistry role-arnはこの順番を使わず、手元の設定ファイルだけを読みます（registry setupは--directoryの下の--configで、既定はartifact-pages.yaml。registry role-arnは--configで明示したファイル）。環境変数、保存した指定、github://は使いません。config set-defaultは、手元のパスなら絶対パスにして、ユーザーの設定ディレクトリのartifact-pages/default-configに保存します。設定の中の相対パス（local.rootなど）は、設定ファイルの場所ではなく、コマンドを実行したディレクトリが基準です。

重ね合わせ

キー重ねたときの扱い
schemaVersionどの層にも必要（整数の1）。
providerと対応するブロック組で1つ。後の層が配信先の設定を丸ごと置き換える。
sites書かなければ前の層を引き継ぐ。書けば丸ごと置き換える（sites: {}も空として置き換える）。
cli、web2つを合わせて、書ける層は1つだけ。別々の層に書くこともできない。

知らないキー、重複したキー、型の違い、複数のYAMLドキュメントは拒否します。手元の層の合計とリモートの設定は、それぞれ512 KiBまでです。

キー

共通

キー内容
schemaVersion必須整数の1。
provider必須local、aws、cloudflareのどれか（ほかに検証用のgcp-local）。
publicBaseURL任意読者が開くURLのオリジン。HTTPS（手元ならHTTPのループバックも可）。パス、クエリ、フラグメントは付けない。プレビューのURLを作るのに使う。
cli.version任意公開を行うCLIの正確な版（MAJOR.MINOR.PATCH）。v、範囲、latest、プレリリースの印は不可。
web.version任意app deployが置く閲覧アプリの正確な版。互換性の確認にも使う。
sites任意登録するサイトのすべて。registry syncとregistry setupでは必須。

local

キー内容
local.root必須配信先にするディレクトリ。公開元と重ならない場所。

aws

キー内容
aws.region必須バケットのリージョン。
aws.accountId任意12桁の文字列。bucketを省くとき、registry setupとregistry role-arnでは必須。
aws.bucket任意既定はartifact-pages-<accountId>-<region>。
aws.distributionId任意CloudFrontのディストリビューション。ないとキャッシュの無効化をしない。
aws.namePrefix任意IAMロールの名前の先頭。既定はartifact-pages。Terraformのname_prefixと同じにする。

AWSの認証情報は、AWS SDKの標準の探し方（環境変数、プロファイル、OIDCで得た一時的な認証情報など）で読みます。

cloudflare

キー内容
cloudflare.accountId、cloudflare.zoneId必須それぞれ32桁の16進数。
cloudflare.publicBaseURL必須HTTPSのオリジン。最上位のpublicBaseURLも書くなら同じ値。
cloudflare.bucket任意既定はartifact-pages。
cloudflare.accessKeyIdEnv任意R2のアクセスキーIDの環境変数名。既定はCF_R2_ACCESS_KEY_ID。
cloudflare.secretAccessKeyEnv任意R2のシークレットの環境変数名。既定はCF_R2_SECRET_ACCESS_KEY。
cloudflare.apiTokenEnv任意APIトークンの環境変数名。既定はCF_API_TOKEN。
cloudflare.sessionTokenEnv任意一時的なR2の認証情報のセッショントークンの環境変数名。R2のキーを明示する方式でだけ使える。
cloudflare.registryReaderAccessKeyIdEnv、registryReaderSecretAccessKeyEnv、registryReaderSessionTokenEnv任意サイトの公開とプレビューで、登録情報と閲覧アプリの記録を読むためだけの別の認証情報の環境変数名。キーとシークレットは組で書く。名前を書いて値がなければ、ほかの認証情報で代わりに読むことはしない。

sites

キー内容
sites.<id>必須サイトID。英小文字と数字をハイフンでつないだ形。assetsは使えない。
sites.<id>.name必須表示名。空白だけは不可。
sites.<id>.description任意説明。
sites.<id>.repository必須owner/repository。URLや.gitは不可。大文字と小文字は区別しない。
sites.<id>.sourcePath必須リポジトリの中の相対パス。全体なら.。..、\、絶対パスは不可。

同じrepositoryとsourcePathの組を、2つのサイトに登録することはできません。

github://の指定

項目仕様
形github://OWNER/REPO[/FILE]?ref=REF。FILEを省くとartifact-pages.yaml。
refブランチ、タグ、SHA。省くと既定のブランチ。その実行で使うコミットに固定し、結果のconfigCommitShaに記録する。
合成リモートの設定は単独で完結させる。手元の層やほかのリモートとは重ねられない。
認証GITHUB_TOKEN、なければGH_TOKEN。非公開のリポジトリにはそのcontents:read。

Cloudflareの認証情報の要否

R2のキー（アクセスキーIDとシークレット）を明示する方式と、APIトークン1つから導く方式があります。キーが2つとも設定されていれば明示する方式、2つとも空ならトークン1つの方式です。片方だけは失敗します。

操作R2のキーCF_API_TOKEN（明示する方式）
site sync要る内容が変わる実行と、残ったキャッシュの削除を続けるとき
preview publish要る通常は要らない。中断したプレビューの片づけを続けるとき
preview remove、app remove要る実際に削除するとき
app deploy、registry sync要る実際にキャッシュを削除するとき
lock inspect、lock recover、config check要る要らない
index build、config set-default、registry setup、registry role-arn要らない要らない

トークン1つの方式では、配信先に触れるすべての操作で、試し実行や変更のない実行も含めてCF_API_TOKENが要ります。トークンには、バケットのWorkers R2 Storage Bucket Item WriteとゾーンのCache Purgeが必要です（「Cloudflareに構築する」）。
