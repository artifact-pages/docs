GitHub Actions

製品は4つのActionsを配っています。どれもCLIを入れて対応するコマンドを実行する薄いラッパーです。ここに書くのはv0.3.0の契約です。管理リポジトリの共通のワークフローの使い方は「管理リポジトリを準備する」にあります。

4つのActions

Action実行するコマンド
artifact-pages/publish-actionsite sync
artifact-pages/preview-actionpreview publish
artifact-pages/registry-actionregistry sync
artifact-pages/app-deploy-actionapp deploy

対応するランナーはLinuxとmacOS（x64、arm64）です。Windowsには対応しません。配信先の認証情報（Cloudflareの環境変数、AWSのロールの引き受け）は、Actionの前のステップかジョブのenvで用意します。削除、--accept-breaking、--reconcileを行う入力はないので、必要な場合はCLIを直接使います。

共通の入力

入力既定意味
config""設定ファイルのパスか、github://の指定1つ。
cli-version""1回だけ使うCLIの正確な版。互換性の確認は行う。
dry-run"false"試し実行にする。
summary"true"ジョブの概要に結果を書く（失敗のときも）。
checkoutautoGitのチェックアウトがなければチェックアウトする。trueで常に、falseでしない。
fetch-depth"1"Actionがチェックアウトするときの深さ。0で全履歴。
publish-on""publish、registry、app-deployだけ。書き込みを許すきっかけを、改行区切りのeventかevent:refで書く（例：push:refs/heads/main）。合わないきっかけでは試し実行になる。空なら制限なし。

チェックアウトは認証情報を残さない設定で行います。github-tokenの入力はありません。

Actionごとの入力

Action入力既定と意味
publishsite必須。サイトID。
source""。省くと登録のsourcePath。
ref""。記録する参照の表示だけ。チェックアウトは変えない。
previewsite必須。
source""。書くなら登録のsourcePathと同じにする。
head""。プルリクエストのイベントではその先頭のSHA、それ以外はHEAD。
default-ref""。プルリクエストのイベントではorigin/<base>、それ以外はorigin/HEAD。
pull-request""。プルリクエストのイベントではその番号。noneでプルリクエストに結び付けない。
include""。追加で含めるファイル（改行区切りのパスかパターン）。
base-url""。省くと設定のpublicBaseURL。どちらもなければ失敗。
comment"false"。"true"でサイトごとに1つのコメントを作り、更新する。コメントの失敗は警告で、プレビューは失敗にしない。
registry共通の入力だけ。
app-deployarchive""。手元のバンドル。省くと設定のweb.version。
repositoryartifact-pages/artifact-pages。

previewのActionは、チェックアウトをプルリクエストのbaseで行い、CLIの版をbaseの設定から選びます。プルリクエストで設定を書き換えて、書き込むCLIを変えることはできません。pull_request_targetとフォークからのプルリクエストは拒否します。

出力

Action出力outcome
共通operation、outcome、result、exit-code、error
publish＋site、changes、preview-changesplanned、synced、no-op、failed
preview＋site、group-list-url、documents、comment-urlplanned、published、no-op、no-preview、failed
registry＋registry-updated、changesplanned、synced、no-op、failed
app-deploy＋changesplanned、deployed、no-op、failed

出力はすべて文字列です。changes、preview-changes、documents、resultはJSONの文字列、registry-updatedは"true"か"false"、exit-codeは整数の文字列です。CLIを入れる前に失敗した場合は、すべての出力があるとは限りません。

権限

  • 通常はcontents: read。
  • previewでcomment: "true"ならpull-requests: write（プレビューのジョブだけに）。
  • AWSのロールをOIDCで引き受けるジョブにはid-token: write。
