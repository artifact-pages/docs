リファレンス

CLI

artifact-pagesは、公開、登録、閲覧アプリの配置、ロック、設定の確認を行う1つのコマンドです。各コマンドの詳しいフラグはartifact-pages <command> --helpで確かめられます。

コマンド

コマンド用途と主なフラグ
site sync登録済みのサイトを1つ同期する。--site（必須）、--source（既定は登録のsourcePath）、--ref（記録する参照の表示だけ）、--reconcile、--config、--dry-run、--format。
preview publish変更したArtifactのプレビューを公開する。--site（必須）、--source、--head（既定HEAD）、--default-ref（既定origin/HEAD）、--pull-request（番号かPRのURL。省くとプルリクエストに結び付けない）、--include（繰り返し可）、--base-url、--config、--dry-run、--format。
preview removeプレビューのグループを削除する。--siteと--group（pr:<番号>かhead:<SHA>）が必須。--config、--dry-run、--format。
registry sync設定のsitesのとおりに登録を反映し、外したサイトを片づける。--config、--accept-breaking、--dry-run、--format。
registry setup管理リポジトリの共通のワークフローを生成する。--directory（既定.）、--config、--repository、--check。
registry role-arnAWSのサイトのロールのARNを表示する。--configと--siteが必須。手元の設定ファイルだけを読み、AWSには問い合わせない。
app deploy閲覧アプリを置く。web.versionのリリースか、--archiveの手元のバンドル。--repository、--config、--accept-breaking、--dry-run、--format。
app remove閲覧アプリのファイルだけを削除する。--config、--dry-run、--format。
lock inspectロックの状態を見る。--site、または--scope registryか--scope application。
lock recover残ったロックを解く。lock inspectと同じ指定と、--observed-etag（必須）。
config checkこのCLIが書く形式と、配信先に記録された形式を、web.versionの閲覧アプリが読めるかを確かめる。書き込みはしない。
config set-default LOCATOR既定の設定の指定を保存する。LOCATOR（手元のパスかgithub://の指定）は必須。
index build手元で一覧だけを作る。公開はしない。--site（必須）、--source、--out（既定.local/storage）など。
compatibility --format jsonこのCLIが読み書きする形式を出力する。
versionCLIの版を表示する（--format jsonも可）。

registry unregisterやsite publishのような取り下げや公開の別コマンドはありません。サイトの取り下げは、sitesから外してregistry syncします。

使うCLIの版

配信先を操作するコマンドは、--cli-version、環境変数ARTIFACT_PAGES_CLI_VERSION、設定のcli.versionの順に版を決めます。いまのCLIと違う版なら、その版をダウンロードし、チェックサムを確かめてから実行を任せます。--cli-versionはコマンド名の前後どちらにも置けます。registry setupとregistry role-arnは、実行したCLIそのものを使い、版の指定を受け付けません。

試し実行

--dry-runは、設定と配信先を読み、何をするかを表示します。ロックの取得、記録の書き込み、配信先への書き込みと削除、キャッシュの変更、ロックの解除はしません。リリースのダウンロードや認証情報の導出は行うことがあります。

出力と結果

結果は既定で文章、--format jsonで標準出力にJSONを出します。失敗の説明は標準エラーに出ます。JSONにはoperation、outcome、changesなどが入り、github://の設定を使った場合はconfigCommitShaも入ります。

操作outcome
site sync、registry syncplanned（試し実行）、synced、no-op
preview publishplanned、published、no-op、no-preview
app deployplanned、deployed、no-op
preview remove、app removeplanned、removed、no-op
config checkchecked
lock inspect、lock recoverinspected、recovered
終了コード意味
0成功。no-opとno-previewも成功です。
2引数、設定、版の指定、Actionsの対応範囲の誤り。
1配信先、ダウンロード、突き合わせ、互換性の確認の失敗。
