# Artifact Pages ドキュメント

Artifact Pagesは、各チームがGitで書いたHTMLとMarkdownのArtifactを、社内のひとつの場所で探して読めるようにする仕組みです。ここでは、リポジトリから公開して閲覧アプリで1ページとして読む、HTMLやMarkdownのファイルを「Artifact」と呼びます。このドキュメントは、それを組織に用意するプラットフォーム担当者に向けて書いています。

導入するかどうかを決めるために全体を1ページでつかむには、[概要](overview.html)を読んでください。

## 組織に提供できるもの

- **チームは自分のリポジトリから公開する。** HTML、Markdownと、それが使うCSSや画像を、ビルドなしでそのまま公開します。公開はGitHub Actionsのジョブで、マージのたびに行えます。Artifactの正本はGitで、Artifact Pagesの中で編集はしません。
- **プルリクエストの変更をプレビューで確かめる。** 変更したArtifactを、本公開とは別の場所に公開して確認できます。プレビューは本公開の一覧や検索には混ざりません。
- **どのチームのArtifactも、同じ画面で探して読む。** 読者はブラウザで共通の閲覧アプリを開き、サイトを切り替え、タイトルやパス、本文の言葉でArtifactを探します。目次、ページや見出しのURL、更新日、GitHubの公開元へのリンクも、どのサイトでも同じように使えます。
- **それぞれが独立して更新される。** 各サイトは、ほかのサイトの公開を待たずに自分の範囲だけを公開します。閲覧アプリもArtifactとは別に更新でき、そのたびに全サイトを公開し直す必要はありません。
- **自社のCloudflareかAWSで動く。** 配信はオブジェクトストレージとCDNだけで、リクエストを処理するサーバーを常に動かす必要はありません。環境はTerraformのモジュールで作ります。

Artifact Pagesには、利用者のアカウントやログイン、サイトごとの閲覧権限はありません。社内だけに見せる制限は、配信先のホスト名に対してIPアドレスやCloudflare Accessなどで設定します。

## 全体の形

ひとつの環境は、管理リポジトリ1つと、Artifactを公開するチームのリポジトリ（以下、サテライトリポジトリ）でできています。

```mermaid
flowchart LR
  admin["管理リポジトリ<br>設定・サイトの登録・共通の公開ワークフロー"]
  teams["サテライトリポジトリ<br>各チームのArtifact"]
  store[("配信先<br>Cloudflare / AWS")]
  reader["閲覧アプリ<br>読者のブラウザ"]
  admin -- "閲覧アプリの配置・サイトの登録" --> store
  teams -- "自分のサイトだけを公開" --> store
  admin -. "共通の公開ワークフローを提供" .-> teams
  store --> reader
```

- **管理リポジトリ**は、配信先の設定、登録するサイトの一覧、CLIと閲覧アプリのバージョンを持ちます。各チームが呼び出す共通の公開とプレビューのワークフローも、ここから配ります。
- **サテライトリポジトリ**は、各チームのふだんのリポジトリです。製品のコードと同じリポジトリでも構いません。Artifact Pagesのために足すのは、公開するArtifactのディレクトリと、共通のワークフローを呼び出す短いワークフローだけです。
- **配信先**には、閲覧アプリと、公開されたすべてのサイトが入ります。
- **閲覧アプリ**は、サイトの一覧と、開いたサイトのArtifactの一覧を読み込み、探す・読むための画面を提供します。
